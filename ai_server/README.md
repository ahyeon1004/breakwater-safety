# 부우산 방파제 안전 관제 — AI 서버

웹캠 영상을 Python(OpenCV)으로 받아 Teachable Machine 모델 3개(사람수·위험도·추락)로 분석하고,
기존 관제 화면(`../index.html`)에 결과를 실시간으로 반영한다. 화면 디자인과 기존 기능(기상 위험도, 지도, 기록 등)은 그대로다.

```
ai_server/
├─ app.py             Flask 서버: 관제 화면 제공 + /api/status + /video/<CAM> + 방송 음성 + 기록 저장
├─ camera.py          카메라 탐색·캡처 (장치 하나당 캡처 하나, 같은 카메라 중복 열기 방지)
├─ models.py          Teachable Machine 모델 로드·전처리·결과 안정화(다수결)
├─ people_counter.py  Teachable Machine 사람수 분류 (비교·보조용)
├─ lego_detector.py   레고 피규어 개별 탐지 (빈 배경과 비교) + 추적 → 피규어별 박스와 PERSON 번호 (기본)
├─ person_detector.py 실제 사람 탐지 (YOLO + ByteTrack, 선택 사항)
├─ camera_check.py    카메라 장치 번호 확인 도구
├─ prepare_models.py  모델 ZIP을 models/ 에 한 번 풀어 두는 도구
├─ config.json        카메라 번호·모델 경로·판단 기준 설정
├─ models/낙상, 사람수, 위험도   (keras_model.h5 + labels.txt)
├─ models/yolo/yolo11n.pt       사람 탐지용 YOLO 사전 학습 가중치
└─ paths.py           실행 중 쓰는 파일의 저장 위치 (프로젝트 밖)

실행 중에 생기는 파일(상황 기록 events.jsonl, AI 판단 변화 ai_events.jsonl, 빈 배경 사진, 카메라 확인 사진)은
**프로젝트 밖** `~/Library/Application Support/BuusanAI/` 에 저장한다. 프로젝트 폴더 안에 쓰면 VS Code Live Server가
파일 변경을 감지해 웹페이지를 계속 새로고침하기 때문이다. 위치는 `config.json`의 `"data_dir"`로 바꿀 수 있다.
Finder에서 열기: `open ~/Library/Application\ Support/BuusanAI`
```

## 0. 가장 쉬운 방법 — AI 서버 없이 브라우저만으로

1. VS Code에서 `index.html`을 **Live Server(Go Live)** 로 연다. (파일을 더블클릭해서 열면 모델을 못 읽음)
2. CCTV 패널의 **📷 카메라 연결** → CAM-01, 카메라 장치(Fifine K420) 선택 → 연결.
   - 연결한 화면에만 영상이 나온다. CAM-02는 직접 연결하기 전까지 `미연결 · 카메라 설정 필요`(자동 복제하지 않음).
3. 브라우저가 직접 티처블 머신 모델 3개(사람수·위험도·추락)를 돌린다. 처음 한 번은 모델을 받느라 10~20초 걸릴 수 있다.
4. 레고를 올리면 **노란 머리가 확인된 레고**에만 초록 박스와 `PERSON n`, `감지 인원 N명`. 레고가 없으면 `레고 감지 대기 (0명)`.
   레고를 모두 치운 상태에서 **🖼 빈 배경 저장**을 해 두면 박스가 몸 전체로 넓어지고, 원래 있던 노란 물체를 걸러낸다(선택).
5. **⚠ 위험 구역 지정**, 안내 방송, 현장 출동, 경보 등은 AI 서버 방식과 똑같이 동작한다.

- 모델은 `web_models/`(티처블 머신 모델을 브라우저용 TensorFlow.js 형식으로 변환한 것, 라벨은 원본 그대로)를 쓴다.
  변환 결과는 원본 Keras 모델과 같은 입력에서 같은 값을 내는 것을 확인했다.
- 인터넷이 필요하다(TensorFlow.js를 CDN에서 받음). 빈 배경과 위험 구역은 브라우저에 저장된다.
- AI 서버 방식과 달리 Mac `say` 음성은 없고 브라우저 음성만 쓴다. 아래 1~4는 **AI 서버 방식**을 쓸 때만 필요하다.
- 모델을 다시 학습했으면 `ai_server/models/`에 넣은 뒤 브라우저용으로 다시 변환해야 한다(변환 방법은 이 문서 끝).

### 아두이노 온습도 센서 (기온·습도 카드, 여러 대)

- **`부우산 시작.command`로 열면 버튼 없이 자동 연결**된다. 화면 서버(`ai_server/page_server.py`)가 USB로 꽂힌 아두이노를
  모두 찾아(나중에 꽂아도 3초 안에) 계속 읽고, 화면은 그 값을 받는다. 기온·습도 카드 큰 숫자는 정상 센서들의 평균,
  아래 줄은 센서별 값(`#1 22.4℃ · #2 23.0℃`)이다. 10초 넘게 값이 없으면 `응답 없음`.
- 아두이노가 보내는 줄은 `T=23.4,H=56.0`, `습도:56% 온도:23도`, `T:23.4 H:56`, `{"t":23.4,"h":56}`, `23.4,56` 등을 읽는다(9600bps).
  예시 스케치: `arduino/온습도센서/온습도센서.ino` (DHT11/DHT22, DATA → 디지털 2번, "DHT sensor library" 필요).
- **온도·습도가 모두 0이면 센서를 못 읽는 것**으로 보고 표시하지 않는다(`값 0(배선 확인)`). 센서 DATA 핀 번호·배선·센서 종류(DHT11/22)를 확인.
- `다른 창이 사용 중`: 같은 포트를 Chrome(이전에 '🔌 아두이노 연결'로 연 화면)이나 Arduino IDE 시리얼 모니터가 잡고 있는 것. 그 창을 닫거나 화면을 새로고침.
- 화면 서버 없이(Live Server 등) 열었을 때만 '🔌 아두이노 연결/추가' 버튼이 보이며, 브라우저 보안상 처음 한 번은 포트를 직접 골라야 한다.
- 보드레이트를 바꾸면 화면 서버는 환경변수 `SENSOR_BAUD`, 브라우저 연결은 ⚙ 설정에서 맞춘다.

## 3. 카메라 확인 (피파인 K420)

1. K420을 USB로 연결한다.
2. 터미널에서 실행한다 (서버가 켜져 있으면 끄고):
   ```bash
   ./run.sh camera_check.py
   ```
   macOS가 인식한 카메라 이름과, 장치 번호 0~4를 하나씩 열어 본 결과(해상도)를 출력하고
   각 장치 사진을 `~/Library/Application Support/BuusanAI/camera_<번호>.jpg`로 저장한다. 사진을 보고 K420이 몇 번인지 확인한다.
3. 처음 실행할 때 macOS가 **카메라 권한**을 물으면 터미널(또는 iTerm)에 허용한다.
   거부했다면 `시스템 설정 → 개인정보 보호 및 보안 → 카메라`에서 켠다.

`config.json`의 카메라 설정:

```json
{ "id": "CAM-01", "device": "auto", "name_hint": "K420", "fallback": true, "width": 1280, "height": 720 }
```

- `"device": "auto"` — 이름에 `K420`이 들어간 카메라만 연다. `"fallback": false`(기본)라 K420이 없으면 맥북 내장 카메라로 바꾸지 않고
  ‘카메라 연결 오류’와 **↻ 재연결** 버튼을 보여 준다. (K420 USB를 다시 꽂고 재연결) 아무 카메라나 쓰려면 `"fallback": true`.
- 번호를 고정하려면 `"device": 1`처럼 숫자를 넣는다. 그 장치만 쓰려면 `"fallback": false`.
- 카메라 없이 연습하려면 `"device": "/경로/영상.mp4"` (영상 파일을 반복 재생).
- macOS 장치 이름과 OpenCV 번호의 대응은 **추정**이다. 확실히 하려면 `camera_check.py`의 사진으로 확인한다.

**CAM-02** 는 기본적으로 `"share": "CAM-01"` — 카메라가 한 대뿐이라 같은 캡처를 복제해 보여 준다.
화면에는 `⧉ CAM-01 복제`로 표시되고 온라인 카메라 수에도 넣지 않는다(실제 카메라 2대처럼 보이지 않게).
두 번째 카메라가 생기면 CAM-02 설정을 `{ "id": "CAM-02", "device": 2 }`처럼 바꾸면 독립 영상·독립 분석이 된다.

- AI 서버가 웹캠을 쓰는 동안에는 화면의 ‘📷 카메라 연결’(브라우저 카메라)을 같은 웹캠에 쓰지 않는다.

## 5. 레고 피규어 개별 탐지 (바운딩 박스 · PERSON 번호)

티처블 머신 모델 3개는 **화면 전체를 분류**할 뿐 레고 하나하나의 위치를 알려 주지 않는다(사람수 모델 = 화면 전체 레고 개수 분류).
사람용 YOLO도 레고를 잡는다는 보장이 없다. 그래서 레고 위치는 다음 방식으로 찾는다(브라우저·AI 서버 모두 같은 방식).

1. **레고 확인 (필수)**: 레고 피규어의 **노란 머리 색**을 찾는다. 방파제(흰색)·테트라포드(파랑·회색)·책상처럼
   노란색이 아닌 것은 화면이 바뀌어도 PERSON 으로 표시하지 않는다. 손(작은 노란 덩어리)은 같은 피규어로 합친다.
2. **빈 배경 (선택, 보조)**: 저장해 두면 ① 배경에 원래 있던 노란 물체는 제외하고 ② 머리와 이어진 몸까지 박스를 넓힌다.
   비교할 때 카메라 자동 노출(화면 전체 밝기 변화)을 보정하고, 그림자처럼 밝기만 바뀐 곳은 색 비율로 비교해 무시한다.
3. 3번 연속(약 0.75초) 확인된 것만 번호를 붙인다. 화면 대부분이 바뀌었거나 노란 덩어리가 너무 많으면 박스 없이 `감지 불확실`.

**시험 결과** (저장하신 실제 모형 배경 사진으로 만든 영상, Chrome 가짜 카메라):
레고 없음 + 밝기 ±20% 출렁임 + 그림자 → 10초 동안 박스 0개 / 레고 2개 → 레고 2개 위치에만 박스 2개, 레고가 사라지면 0개.
**실제 K420 + 실제 레고로는 아직 확인하지 못했다.**

**한계**: 머리가 노란색이 아닌 피규어(살구색 등)는 잡히지 않는다 → `config.json`의 `lego.head_hue`(OpenCV 색상 0~180)를 그 색으로 바꾼다
(브라우저 방식은 `index.html`의 `LEGO` 값). 조명이 너무 어두우면 `head_sat_min`·`head_val_min`을 낮춘다.
노란 물체가 레고 근처에 새로 놓이면 레고로 잡힐 수 있다. 더 정확하게 하려면 레고 사진에 박스를 그려 객체 탐지 모델을 추가 학습해야 한다.

### 위험 구역

CCTV 패널의 **⚠ 위험 구역 지정** → CCTV 화면에서 위험 구역(예: 방파제 끝, 테트라포드)의 꼭짓점을 3개 이상 차례로 누름 →
버튼(‘✔ 구역 저장’)을 다시 누르면 저장된다. 점 없이 다시 누르면 구역이 삭제된다.
피규어 박스의 **발 위치(아래 가운데)** 가 구역 안에 있으면 그 박스가 빨간색 `PERSON n · 위험 구역`으로 바뀌고,
2초 이상 유지되면 ‘AI 위험 구역’ 경보(이유: 위험 구역 진입: PERSON n)가 발생한다. 위험도 모델의 ‘위험’ 판단도 같은 경보의 근거가 된다.

### 두 카메라와 중복 집계

- 카메라가 한 대면 CAM-02는 CAM-01 **복제 화면**이다. 같은 영상이므로 인원은 CAM-01만 센다 → 중복 없음(정확).
- 서로 다른 카메라 두 대를 쓰면(`config.json` CAM-02의 `share`를 지우고 `device` 지정) 카메라마다 따로 탐지하고 번호도 따로 붙인다.
  두 영상의 레고가 **같은 레고인지 확인하는 기능은 없다**(카메라 사이 위치 보정·외형 비교 미구현). 그래서 `overlap` 설정에 따라:
  - `"unknown"`(기본): 전체 인원을 `최소~최대`로 표시하고 ‘전체 인원 추정 · 두 카메라 중복 확인 필요’ (최소 = 두 카메라 중 큰 값, 최대 = 합계)
  - `"regions"`: 각 카메라 화면에서 서로 겹쳐 찍히는 영역을 지정 → 겹치는 영역 밖은 그대로 더하고 안쪽은 많은 쪽만 세서 추정. 여전히 ‘추정’으로 표시
  - `"none"`: 두 카메라 촬영 영역이 **겹치지 않는 것을 직접 확인했을 때만**. 합계를 확정값으로 표시 (겹치는데 이 값을 쓰면 중복으로 세어짐 — 시험에서 확인)
- 테스트(서로 겹치게 찍은 합성 영상 2개, 실제 레고 4개): unknown → 3~5, regions → 4~5, none → 5(겹치므로 틀림).

### 브라우저 카메라 (📷 카메라 연결)

AI 서버 없이 브라우저로 웹캠을 연결하면 **영상만** 보여 준다. 예전의 실제 사람 인식(COCO-SSD)은 레고에 맞지 않고 브라우저를 무겁게 해서
기본으로 껐다(설정 ⚙에서 켤 수 있음). 레고 탐지·PERSON 번호는 🤖 AI 서버에 연결했을 때 동작한다.

### 사람용 YOLO (선택)

실제 사람으로 시연할 때만 `mode: "yolo"`. 가중치는 `prepare_models.py --yolo`로 내려받는다(`models/yolo/yolo11n.pt`).

## 6. 판단·경보 규칙

| 항목 | 규칙 (값은 `config.json`, `index.html` 상단 상수에서 조정) |
|---|---|
| 결과 안정화 | 0.25초마다 추론, 최근 8회 중 60% 이상 같은 결과이고 평균 신뢰도가 기준(사람수 0.6, 위험도 0.7, 추락 0.75) 이상일 때만 확정. 아니면 **판별 중 / 감지 불확실(확인 필요)** 로 표시하고 숫자·경보를 만들지 않음 |
| 위험 구역 경보 | ‘위험’이 2초 유지되면 1번 발령. 안위험·추락 미감지이 8초 유지되면 자동 해제(기록 남김) |
| 추락 의심 긴급 경보 | ‘추락’이 2초 유지되면 발령(위험 구역 경보보다 우선, 진행 중인 위험 경보는 긴급으로 격상). 담당자 확인 창이 뜨고 출동 버튼이 강조됨. 정상이 8초 유지되면 **해제 대기** — 담당자가 ‘상황 종료’로 해제 |
| 중복 방지 | 진행 중인 경보는 다시 만들지 않음. 담당자가 종료한 뒤에도 AI가 계속 위험이면, 정상이 확인된 다음에만 새 경보 |
| 종합 위험도 점수 | 기존처럼 **기상 데이터**로 계산(변경 없음). AI 결과는 위험도 패널의 ‘AI 영상 분석’ 항목에 따로 표시하며, 모델이 내놓지 않는 점수는 만들지 않음 |
| AI 연결 끊김 | 3초 이상 응답이 없으면 ‘AI 연결 끊김 · 분석 중단’ 표시, 이전 결과·인원은 지움. 진행 중인 경보는 유지하되 ‘확인 불가’로 표시. 5초 간격으로 12번만 다시 시도하고, 그 뒤에는 위험도 패널의 **↻ 재연결** 버튼으로 |
| 카메라 연결 실패 | 3번만 다시 시도하고 멈춤(`retries`). 원인을 화면에 표시하고 **↻ 재연결** 버튼으로 다시 시도 |
| 분석 주기 | TM 모델 3개 초당 약 3회(`analysis.interval_sec` 0.3), 레고 탐지 초당 4회. 화면 영상은 초당 12장·너비 960(`stream_fps`, `stream_max_width`) |

**안내 방송**: ‘안내 방송’ 버튼 → 경보에 맞는 문구가 자동 선택됨 → 음성 출력 선택
(브라우저 음성 합성 / Mac `say` 음성 / 음성 없이 문구만). 같은 문구는 20초 안에 다시 송출되지 않는다.
외부 스피커·현장 방송 장비와는 **연결되어 있지 않다** — 이 컴퓨터의 오디오 출력으로만 재생한다.
자동 방송은 기본 꺼짐이며 설정(⚙) → 시연 도구에서 켤 수 있다.

**현장 출동 요청**: 확인 창에서 승인하면 ‘현장 출동 요청 접수 (시연)’ 상태가 된다.
경찰·외부 출동 시스템과는 **연결되어 있지 않으며** 실제로 전달되지 않는다.

**상황 기록**: 기존 기록 목록에 [카메라] 표시와 함께 남고, CSV에 카메라·경보 유형·감지 인원·위험도 모델·추락 모델 열이 추가됐다.
브라우저 저장소에 더해 AI 서버 연결 중에는 `~/Library/Application Support/BuusanAI/events.jsonl`에도 저장되어 브라우저를 바꾸거나 서버를 재시작해도 남는다.
`http://127.0.0.1:5050/api/log` 에서 확인할 수 있다.

## 7. 발표 시연 절차

준비: 서버 실행 → Chrome에서 http://127.0.0.1:5050/ → 카메라가 **방파제 모형만** 비추도록 고정 → 화면을 한 번 누르고 🔔 경보음 켜기
→ 레고를 모두 치우고 **🖼 빈 배경 저장** → **⚠ 위험 구역 지정**으로 방파제 끝 쪽을 구역으로 지정.
시작 전에 ‘기록 비우기’(필요하면 CSV 저장 후)를 해 두면 시연 기록만 깔끔하게 남는다.

1. **사람 없음 장면** — 빈 방파제 모형. CCTV에 `감지 인원 0명`, 위험도 패널 ‘AI 판단: 정상 · 평시 감시’, ‘경보 없음 · 평시 감시 중’.
2. **정상 장면** — 레고 사람을 안전한 곳(입구 쪽)에 세운다. 레고마다 초록 박스·`PERSON n`, `감지 인원 N명`, 상단 ‘방파제 내 감지 인원’ 갱신. 경보 없음.
3. **위험 구역 장면** — 레고 사람을 지정한 위험 구역(방파제 끝/테트라포드 위)으로 옮긴다. 박스가 빨갛게 바뀌고 약 2초 뒤
   CCTV에 ‘⚠ 위험 구역 감지’, 경보 현황에 ‘AI 위험 구역’, 진행 중 경보 +1, 기록에 감지 시간·카메라.
   → **안내 방송** 버튼 → ‘위험 구역 안내 (AI)’ 문구 확인 → 송출(음성 재생, 기록).
   → 레고 사람을 안전한 곳으로 옮기면 8초 뒤 자동 해제(기록).
4. **추락 장면** — 레고 사람을 쓰러뜨린다. 약 2초 뒤 ‘🚨 긴급: 추락 의심’ 창 + 경보음, CCTV에 ‘⚠ 추락 의심 감지’,
   위험도 배지 ‘긴급 · 추락 의심’, 출동 버튼 깜빡임. → **담당자 확인** → **현장 출동** → ‘출동 요청 접수’
   → 안내 방송 ‘추락 의심 긴급 안내 (AI)’ → 레고를 세우면 8초 뒤 ‘해제 대기’ → **상황 종료**.
5. **연결 끊김** — 서버 터미널에서 `Ctrl + C` → 3초 안에 ‘AI 연결 끊김 · 분석 중단’. 서버를 다시 켜면 자동 복구.

시연 전 리허설에서 각 장면마다 CCTV 왼쪽 아래의 모델 판단(인원/위험도/추락과 신뢰도)을 보고,
조명·카메라 각도를 학습 때와 비슷하게 맞춘다.

## 8. 한계와 주의

- **Teachable Machine 분류 모델은 처음 보는 장면도 반드시 학습한 클래스 중 하나로 답한다.** 개발 중 시험에서
  모형이 아닌 장면(방 안, 단색 테스트 영상)에도 ‘위험’, ‘사람 2명’을 높은 신뢰도로 내놓았다. 카메라에는 모형만 보이게 하자.
- 레고 개별 탐지(배경 비교)는 **테스트용 합성 영상으로만 확인**했다. 실제 레고·조명·그림자에서는 시연 전에 반드시 리허설하고
  `diff_threshold`·`min_area`를 조정한다. 붙어 있는 레고는 1명으로 잡히며, 화면에는 탐지된 만큼만 표시한다(숫자를 맞추려고 지어내지 않음).
- CCTV 속 사람 위치를 방파제 거리로 바꾸는 보정은 하지 않아 지도에는 사람 점을 찍지 않는다(‘위치 미상’).
- Ultralytics(YOLO) 라이브러리는 AGPL-3.0 라이선스다. 학교 발표용으로는 문제없지만 상업적으로 배포하려면 라이선스를 확인해야 한다.
- ‘추락 의심’은 모형의 쓰러진 자세 분류 결과이지 실제 추락 확인이 아니다.
- Mac 음성(`say`)은 AI 서버를 실행한 컴퓨터에서 재생된다. 한국어 음성(Yuna 우선, 없으면 설치된 다른 ko_KR 음성)을 쓴다.
